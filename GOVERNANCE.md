# Governance and Delivery

Status: **proposed initial charter; not adopted**. Human review and explicit adoption are required.

## Status and authority

This is a proposed charter awaiting human review. `main` was initialized with non-authoritative placeholders; substantive documents are submitted on a feature branch. Repository creation, publication, passing checks, and a merge do not by themselves grant operational authority.

An authorized organization human owns charter adoption and amendments. Repository maintainers retain their own security and review responsibilities; affected people retain consent rights. The identity of long-term charter maintainers, reviewer quorum, and escalation owner has not been appointed by this proposal.

## Initial human charter stewardship (proposed)

Until a separate human decision appoints maintainers and review rules, the authorized `usekarma` organization owner acts as the initial charter steward for **proposed** amendments and adoption decisions. This is a responsibility proposal, not a grant of permissions or a claim identifying a particular person. The steward reviews the exact proposed revision, records a dated decision with scope and rationale, and must seek affected domain owners' review for changes to their authority, consent, security, or implementation contracts. Silence, GitHub write access, agent output, or merging a pull request is not approval. If the owner's authority or domain-owner identity is uncertain, stop for human resolution; no agent may appoint itself or infer consent. Formal maintainer appointments, quorum, escalation and branch protection remain open decisions.

## Initial adoption

1. Review the substantive pull request at its exact final commit, including sources, capability labels, privacy boundaries and unresolved decisions below.
2. Record an explicit human adoption decision identifying the accepted commit/version, scope, effective date, reviewer/authority, and any deferred questions or rejected sections. Update the status in a reviewed commit before treating the charter as adopted. Do not backdate adoption.
3. Merge only through a separately authorized human process. The agent preparing this proposal must not merge or self-record adoption.
4. Plan any repository-specific alignment as separate reviewed changes. Adoption does not rewrite another repository's contracts or relax its controls.

If only the documentation is accepted for preservation, record that narrower disposition; keep architectural adoption pending. This process is a proposed human workflow, not an implemented automated gate.

## Amendment and review

Use a feature branch and pull request describing the concrete problem, affected responsibilities/contracts, evidence, alternatives, failure risks, privacy implications and migration needs. Pin claims to source revisions. Preserve earlier decisions in Git history and link superseding rationale. Human review must distinguish changed principles from updated capability observations.

Require the relevant domain or repository owner to review ownership, authority, consent, or security changes. If roles are not assigned or instructions conflict, stop for an explicit human resolution. Organization-level guidance cannot bypass a stricter repository boundary. GitHub administrative permission is not domain consent.

## Execution and approval boundary

Consequential actions require a separately recorded, authorized approval for the exact operation, artifact/plan and target, with applicable freshness, expiry and cancellation checks. This includes cloud/config publication, deployment, destruction, IAM/identity changes, device provisioning, financial operations, and clinical/external care actions. Passing quality gates, issue closure, a queue priority, a simulated decision, or an editable environment flag is not approval.

Changes in approval dependencies require re-review under the target contract. Agents cannot set an acknowledgement to authorize themselves. Existing active-program and single-active-task boundaries remain in force. This repository does not create an executor or dispatch agents.

## Public repository boundary

Publish architectural roles and reviewed non-sensitive summaries only. No private records, family identities, balances, medication details, credentials, unredacted receipts, raw Terraform plans or operational identifiers belong here. Restricted source links may be inaccessible to public readers; their existence does not grant access or certify underlying facts. Disclosure or retention conflicts require a scoped human decision.

No organization-wide community health policy, automated workflow, ruleset, deployment environment, or security-setting change is introduced by this bootstrap. GitHub's organization profile is public documentation; it is not a capability or authority endpoint.
